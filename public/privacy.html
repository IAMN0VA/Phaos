Medical imaging may contain highly sensitive personal information. Treat every study as private even when visible identifiers have been removed.

Local processing

SCAN//SPACE is designed so selected image files are processed in the browser session. The application does not include analytics, advertising, crash-reporting, account tracking, or a medical-image upload service.

What stays in memory

During the session, decoded images, DICOM metadata needed for rendering, measurements, markers, and viewer state may exist in browser and GPU memory. Choosing New Study reloads the application and clears the current in-memory session. Closing the tab also ends the session.

Exports

PNG export contains only the rendered viewport and a visualization-only footer. JSON export uses a privacy-minimized schema that intentionally excludes patient names, dates of birth, accession numbers, filenames, Study/Series/SOP UIDs, and raw DICOM metadata. Marker labels are user-entered content; do not type identifying information into a marker if you plan to share an export.

Network behavior

The production application is intended to operate without third-party analytics or telemetry. Deployment should serve application assets from the same origin. If a deployer adds monitoring, analytics, cloud storage, user accounts, or remote fonts, the privacy notice must be updated before use.

Security

Use SCAN//SPACE only over HTTPS on deployments you trust. Do not use shared or public computers for identifiable studies unless local policy permits it.

Contact and governance

A production operator should publish a privacy contact, retention policy, incident process, and jurisdiction-specific privacy documentation before accepting identifiable studies from the public.
